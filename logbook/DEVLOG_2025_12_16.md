# Development Log - Y300 UHF RFID Reader Integration

**Date:** December 16, 2024
**Task:** Integrate Y300 UHF RFID reader module with ESP32 via UART

## Objective

Integrate Y300 (R300-based) UHF RFID reader module with ESP32 via UART2 for real-time contactless tag detection. Module provides 2-3 meter range for hands-free attendance tracking.

## Problem

ESP32 transmitted commands to Y300 successfully (reset command triggered audible beep), but received zero bytes in response.

## Solution

### 1. Protocol Correction

Initial implementation used incorrect protocol assumptions. Corrected per R300 specification V2.2:

**Changed from:**
- Frame header: `0xBB 0xBB` → `0xA0`
- Checksum: CRC16 → Simple sum `(~sum) + 1`
- Baud rate: 9600 → 115200 bps

**Correct frame format:** `[0xA0][Len][Addr][Cmd][Data...][Check]`

### 2. Hardware Fix

**Root cause:** Wiring error in physical connections
**Fix:** Corrected Y300-to-ESP32 wiring:
- Y300 TX → ESP32 GPIO16 (UART2 RX)
- Y300 RX → ESP32 GPIO17 (UART2 TX)
- Y300 GND → ESP32 GND (common ground)

**Result:** Reset command worked immediately and UART RX buffer received data.

## Implementation

### Commands Implemented
1. **Reset (0x70)** - Initializes module (audible beep, no response data)
2. **Firmware info (0x72)** - Get firmware version
3. **Real-Time Inventory (0x89)** - Continuous tag scanning

### Software Architecture
- Background UART RX task processes incoming frames
- Callback-based design for tag detection events
- Thread-safe statistics tracking (mutex-protected)
- Frame parsing with checksum validation
- Integrated with existing GPIO system

## Technical Notes

- Frame header: Single byte `0xA0`
- Checksum: `(~sum_of_bytes) + 1` per protocol section 6, page 43
- Default baud: 115200 bps
- Real-time inventory streams tags immediately (not buffered)
- UART2 selected for GPIO16/17 - no conflicts with console or strapping pins
- Common ground critical for reliable communication

### Tag Data Structure
Response includes EPC, RSSI, Antenna ID, Frequency parameter, and Protocol Control bytes.

## Key Takeaways

1. Consult specification first - would have prevented protocol debugging
2. Hardware diagnostics essential - RX test tool revealed wiring issue
3. Incremental validation effective - tested simple reset before complex inventory mode
4. Physical wiring errors can mask software issues - test hardware layer first
