# Development Log - MVP Dashboard Implementation

**Date:** January 30–31, 2026
**Task:** Implement web dashboard for lighthouse management and scan event viewing

## Objective

Create a functional web dashboard for managing lighthouse devices, organizing them into groups for direction detection, and viewing real-time scan events.

---

## 1. Database Schema Changes

### New Table: `lighthouse_groups`

Supports pairing lighthouses for direction detection (entry/exit determination). Maximum 2 lighthouses per group (INSIDE + OUTSIDE placement).

### New Enum: `scan_source`

Distinguishes between real-time and offline-synced scans:
- `realtime` - Live tag detections
- `offline_sync` - Backfilled from device cache

Added `source` column to `raw_scans` table.

### Other Changes

- Added `groupId` foreign key to `lighthouses` table (SET NULL on delete)
- Removed unused `label` column from `lighthouses`

**Migration:** `0002_fuzzy_silver_fox.sql`

---

## 2. Backend API Extensions

### Pending Device Workflow

Changed from auto-registration to explicit claiming:

- `GET /api/v1/devices/pending` - List connected but unregistered devices
- `POST /api/v1/devices/pending/:deviceId/claim` - Register device with name, placement, optional group

### Group Management

- `GET /api/v1/groups` - List groups with members
- `POST /api/v1/groups` - Create group
- `PATCH /api/v1/groups/:id` - Update group
- `DELETE /api/v1/groups/:id` - Delete group (unlinks members)

### Scans Query

- `GET /api/v1/scans` - Filter by lighthouse, EPC (partial), source, date range; paginated

### Route Ordering Fix

Public routes must be defined before protected route mounting to prevent auth middleware blocking.

---

## 3. Frontend Implementation

Selected SolidJS for smaller bundle size and fine-grained reactivity. Styling with SCSS modules.

**Three pages:**
- **Lighthouses** (`/`) - Pending devices with claim modal, registered lighthouses with status
- **Groups** (`/groups`) - Group management with create/edit/delete
- **Events** (`/events`) - Filterable scan table with real-time WebSocket updates

### Vite Proxy Fix

Initial configuration intercepted source module imports. Fixed by excluding source paths - only `/api/*` and `/ws` routes proxy to backend.
