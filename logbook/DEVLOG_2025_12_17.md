## Objective

Add RF power and frequency configuration capabilities to Y300 RFID reader to maximize detection range and optimize for regional spectrum requirements.

## Implementation

### 1. Power Control (Command 0x76)

Implemented transmit power configuration per R300 protocol section 2.1.7, page 12.

**API Added:**
```c
esp_err_t rfid_reader_set_power(uint8_t power_dbm);
```

**Features:**
- Valid range: 20-33 dBm with automatic clamping
- Higher power = longer read range (up to 3+ meters)
- Default module power insufficient for attendance use case
- Command format: `[0xA0][0x04][Addr][0x76][Power][Check]`

**Implementation Notes:**
- Input validation with range clamping prevents invalid values
- Explicit logging of configured power level
- Must be called after module initialization

### 2. Frequency Region Configuration (Command 0x78)

Implemented spectrum configuration per R300 protocol section 2.1.9, page 13.

**API Added:**
```c
esp_err_t rfid_reader_set_frequency_region(uint8_t region,
                                           uint8_t start_freq,
                                           uint8_t end_freq);
```

**Regional Standards:**
- `RFID_REGION_FCC` (0x01): 902-928 MHz (USA) - best range
- `RFID_REGION_ETSI` (0x02): 865-868 MHz (Europe)
- `RFID_REGION_CHN` (0x03): 920-925 MHz (China)

**Frequency Parameters:**
- `RFID_FREQ_902MHZ` (0x07)
- `RFID_FREQ_915MHZ` (0x21)
- `RFID_FREQ_928MHZ` (0x3B)
- Full frequency table documented on protocol page 41

### 3. Continuous Inventory Auto-Restart

Fixed inventory mode to operate continuously without manual restarts.

**Problem:** Real-time inventory (0x89) stops after each round completes, requiring manual restart.

**Solution:**
- Implemented inventory completion packet detection
- Completion packet format: `[0xA0][0x08][Addr][0x89][Ant_ID][Total(4)][Check]`
- Auto-restart logic with 10ms delay between rounds
- Parser distinguishes completion packet from tag data

**Implementation:**
```c
static bool is_inventory_complete(const uint8_t* data, uint16_t len)
{
    return (len == 11 &&
            data[0] == R300_FRAME_HEAD &&
            data[1] == 0x08 &&
            data[3] == R300_CMD_INVENTORY_RT);
}
```

**Result:** Truly continuous operation for real-time attendance tracking.

### 4. Performance Optimization

**Channel Parameter Tuning:**
- Changed from single-channel (0x01) to full-spectrum (0xFF)
- 0xFF enables fastest scanning: 30-50ms per inventory round
- Frequency hopping improves reliability in noisy RF environments
- Per section 2.2.8, page 27: channel parameter controls hopping behavior

**UART RX Task Refactor:**
- Added completion packet handling in main loop
- Separated tag detection from completion detection
- Improved logging with round completion statistics
- Debug-level logging shows total reads per round

## Technical Details

### Power Configuration
- Command 0x76 per R300 protocol V2.2 section 2.1.7
- Valid range enforcement prevents hardware damage
- Power settings persist until module reset
- Higher power increases range but also increases power consumption

### Frequency Configuration
- Command 0x78 per R300 protocol V2.2 section 2.1.9
- Regional compliance critical for legal operation
- Frequency hopping improves interference resistance
- Start/end frequency defines operational bandwidth

### Continuous Inventory Flow
1. Send 0x89 command with channel=0xFF
2. UART RX task receives tag detection packets
3. Invoke callback for each detected tag
4. Detect completion packet (Len=0x08)
5. Wait 10ms to prevent command flooding
6. Auto-restart with new 0x89 command
7. Repeat indefinitely until stop requested
