# Development Log - Charger Reverse Engineering & Dev Hotspot

**Date:** February 5–10, 2026
**Task:** Reverse-engineer battery charger module; implement dev hotspot utility

## Objective

Two parallel workstreams: understand the off-the-shelf TP4056/DW01HA charger module well enough to integrate its circuit onto the production PCB; and create a dedicated dev hotspot using a second ESP32 to eliminate dependence on external network infrastructure during field testing.

---

## 1. Battery Charger Module Reverse Engineering

### Module Overview

The target module combines two ICs:

| IC     | Function                                                           |
|--------|--------------------------------------------------------------------|
| TP4056 | Single-cell lithium battery charger                                |
| DW01HA | Battery protection IC (over-charge, over-discharge, short circuit) |

Datasheets added to `docs/` for reference.

### Approach

The module was reverse-engineered by tracing its PCB and measuring component placements. At this stage the schematic topology is understood but component values (resistor/capacitor ratings) are not yet confirme, measurements pending.

### Key Circuits to Integrate

**TP4056 charge current:** Set by a single resistor (`PROG` pin to GND). Value determines charge current — will be selected based on intended battery capacity.

**DW01HA protection circuit:** Sits between the TP4056 output and the battery terminals, with back-to-back MOSFETs controlled by the DW01HA for over-charge/over-discharge cutoff.

**Reference:** `docs/tp4056.pdf`, `docs/DW01HA.PDF`

## 2. Dev Hotspot (`softap_bridge`)

### Problem

Field testing requires the lighthouse firmware to connect to an MQTT broker on a known network. Relying on an external access point or phone hotspot introduces variables and makes reproducible testing harder.

### Solution

A dedicated second ESP32 running a minimal `softap_bridge` firmware acts as a fixed-SSID access point with WPA2-PSK security. This provides a stable, always-available network for development without any external dependencies.

**Configuration:**
- SSID: `lighthouse-dev`
- Password: `lighthouse`
- Security: WPA2-PSK

This is a **development-only tool** and will not appear in the production system.
