# Development Log - ESP32 GPIO Implementation

**Date:** December 15, 2024  
**Task:** Implement GPIO control for buttons, LEDs, and PIR sensor  
**Status:** ✓ Complete - All peripherals functional

## Objective

Create ESP32 GPIO application with debounced button inputs, LED outputs, and PIR motion sensor integration for the attendance system development board.

## Implementation

### Components Configured
- **LED Outputs:** GPIO5, GPIO18 (100Ω resistors)
- **Button Inputs:** GPIO34, GPIO35 (external 10kΩ pull-ups required)
- **PIR Sensor:** GPIO2 (initially GPIO3, changed due to strapping pin conflict)

### Key Features
- 20ms software debouncing for buttons
- 100ms debouncing for PIR sensor
- ISR-based edge detection with deferred processing in main task
- Press counting and state tracking

## Issues Encountered

### GPIO3 Restriction
**Problem:** PIR sensor on GPIO3 didn't work  
**Cause:** GPIO3 is U0RXD (UART0 RX) and a strapping pin used during boot  
**Solution:** Moved to GPIO2

### Onboard LED on GPIO2
**Observation:** GPIO2 has hardwired onboard LED on Hornaxys devboard  
**Result:** LED lights during motion detection (acceptable visual indicator)  
**Note:** GPIO34/35 buttons don't trigger this as they have no onboard LEDs

## Technical Notes

- GPIO34/35 are input-only pins with no internal pull-up/pull-down capability
- External pull-ups are mandatory for stable operation
- Strapping pins (GPIO0, GPIO2, GPIO3, GPIO15) require careful consideration
- Datasheet references added throughout code (ESP32 Series Datasheet v5.2)
