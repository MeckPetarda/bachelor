## 2. Database Schema Design

Established complete schema using Drizzle ORM with eight core tables:

| Table              | Purpose                                    |
|--------------------|--------------------------------------------|
| `lighthouses`      | Device registration and configuration      |
| `raw_scans`        | Immutable audit log of RFID detections     |
| `processed_events` | Derived entry/exit events                  |
| `users`            | User records with optional personal data   |
| `tag_assignments`  | RFID tag to user mappings                  |
| `mqtt_clients`     | Connection tracking for lighthouse devices |
| `audit_logs`       | Change tracking for compliance             |
| `dashboard_users`  | Admin authentication                       |

### Naming Convention

All schema definitions use camelCase for TypeScript properties with automatic snake_case conversion in PostgreSQL via Drizzle's casing configuration:

```typescript
// TypeScript: camelCase
lighthouseId: integer().notNull()

// PostgreSQL: snake_case
lighthouse_id INTEGER NOT NULL
```

### Key Design Decisions

**rawScans as immutable audit log:**
- Never modified after insertion
- `processed` flag marks event processing status
- Enables replay and forensic analysis

**Tag assignment with soft deactivation:**
```typescript
uniqueIndex("idx_tag_assignments_active")
  .on(table.tagEpc)
  .where(sql`deactivated_at IS NULL`)
```
- Only one active assignment per tag
- Historical assignments preserved

## 3. PostgreSQL Connection Pool (Task 1.3)

Implemented connection pooling with health monitoring:

```typescript
const pool = new Pool({
  connectionString: config.databaseUrl,
  max: 20,
  idleTimeoutMillis: 30000,
  connectionTimeoutMillis: 2000,
})
```

| Parameter             | Value   | Rationale                    |
|-----------------------|---------|------------------------------|
| `max`                 | 20      | Balance concurrency/overhead |
| `idleTimeoutMillis`   | 30000   | Release unused connections   |
| `connectionTimeoutMillis` | 2000 | Fail fast on DB issues      |

Added graceful shutdown handling to properly drain connections.

## 4. MQTT Broker Integration (Task 1.4)

Embedded Aedes MQTT broker directly in the server process:

```typescript
const broker = Aedes()
const mqttServer = createServer(broker)
mqttServer.listen(1883)
```

### Message Handlers

| Topic Pattern              | Handler                          |
|----------------------------|----------------------------------|
| `lighthouse/+/scan`        | Process RFID scan events         |
| `lighthouse/+/health`      | Update device health metrics     |
| `lighthouse/+/status`      | Track online/offline transitions |

### Benefits of Embedded Broker

- No external Mosquitto dependency
- Single deployment artifact
- Direct database access from handlers
- Simplified development environment

## 5. REST API Endpoints (Task 1.5)

Implemented core API routes using Hono framework:

### Endpoints

| Method | Path                 | Purpose                    |
|--------|----------------------|----------------------------|
| POST   | `/api/auth/login`    | JWT token generation       |
| GET    | `/api/lighthouses`   | List registered devices    |
| POST   | `/api/lighthouses`   | Register new device        |
| GET    | `/api/users`         | List users                 |
| GET    | `/api/events`        | Query processed events     |

### JWT Authentication Middleware

```typescript
const authMiddleware = async (c, next) => {
  const token = c.req.header('Authorization')?.replace('Bearer ', '')
  const payload = await verify(token, config.jwtSecret)
  c.set('user', payload)
  await next()
}
```
